## Required prospective stages

| Stage | Required evidence before a future result can be accepted |
|---|---|
| `capture_pre` | Independent trusted predecessor revision/digest; owner, receiver/source IDs, route/key IDs, allocation presence, receipt-time probability and diagnostic digest; no future outcome in the capture schema. |
| `bind_delivery` | Own delayed result source, matching owner and both IDs, original fixed receiving-clock delay; shuffled source address is not a time coordinate. |
| `prepare_delta` | Each engine computes its own nine-credit candidate from matched observations. A common read-only oracle may inspect candidates but may not generate either engine's after-values. |
| `validate_serialized` | Exact typed before/after comparison, nine route updates, 36 changed/399 unchanged learning fields, metadata accounted separately, no absorbed required additions. |
| `atomic_commit_consume` | Compare-and-swap the expected predecessor revision/digest; publish core changes, allocation metadata, consumed receiving ID and successor revision in one atomic transaction. |
| `readback` | Read the committed storage through an independent reader and compare actual bytes/typed differences, rather than reuse the candidate or its claimed counters. |
| `record_commit_receipt` | Bind committed revision, receiving identity, consumed status, readback digest and requested/actual field counts to one receipt. |

The required transaction or durable journal implementation must be selected and frozen before implementation. Recovery must yield either the entire predecessor with an unconsumed receipt or the entire successor with a consumed receipt. Partial credits, mixed state generations, double application, state-only commit and consumption-only commit must be refused. Repeating a read-only validation is permitted and is not model application. These are normative requirements; this phase does not demonstrate storage atomicity, durability or exactly-once behavior.

Every role has `local_sparse_reference` and `independent_event_driven_scalar` schema descriptors, with distinct declared after-state producers. Candidate, permanent and shuffled roles are compared only to the same role. All 42 stage bindings are ordered schema entries, **not observed runtime events**. Declared separate producer IDs do not establish implementation independence; real source/execution evidence remains necessary. Diagnostic selection stays isolated from training addresses and learning state.
