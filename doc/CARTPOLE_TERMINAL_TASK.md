# CartPole-v1 Terminal-Feedback Task Contract

The [task contract](../data/processed/benchmark_fixtures/cartpole_terminal_task_v1.json) is fixed at SHA-256 `9033600e3a29e7cfdf7ae7d01927500bfa6b4e737200aaef7f0c0cfd9f702f1a`. The [bounded event adapter](../src/sara_engine/evaluation/cartpole_sparse_reward.py) is SHA-256 `68f34d7650508f484da776a0c1480bc557825da87a376866a7e6119e425f3f5c`. The read-only API inspection passed on Python 3.10.18, NumPy 1.25.2, and Gymnasium 1.0.0; it checked the standard 4-observation/2-action/500-step CartPole-v1 interface and one unscored deterministic transition.

The environment's physics, observations, action set, termination, and time limit remain those of [Gymnasium CartPole-v1](https://gymnasium.farama.org/environments/classic_control/cart_pole/). This is **not** the default-reward benchmark: the default +1-per-step learning signal is discarded. The proposed research signal is emitted once after the episode ends, equal to `steps / 500`, so it is temporally sparse but still carries graded episode-length information. Do not compare its learning returns directly with a default-reward CartPole result. Report mean episode length and the fraction of 500-step episodes separately.

All arms will see the same four input scalars through the same fixed, bounded adapter: one of five bins per channel becomes one route event, four events per observation, and the environment step index is explicit time. No future observation or terminal outcome enters the current decision. Five run IDs use disjoint explicit reset seeds for 128 training, 32 development, and 32 sealed held-out episodes per run. Development and held-out policies do not update. Count observation encoding, decisions, terminal local credit, state maintenance, CPU, input events, and internal event work; CPU or spike counts are not physical energy measurements.

The [policy kernel](../src/sara_engine/evaluation/cartpole_local_policy.py) is implemented at SHA-256 `6be36040ab613f3685353a093349346c5841bde075d9fee81c9095bc93634be7`. It has three arms: scalar route weights, a compact fixed-index event backend, and explicit stateful spiking neurons. All use the same four observed route events, two actions, epsilon-greedy random draws, bounded per-route/action eligibility (`0.99` decay), one terminal local update (`0.05 × (outcome − 0.5) × eligibility`), and clamped weights. The compact backend is intentionally a behavioral-equivalence control, not a separate learning algorithm. The spiking arm adds membrane/refractory dynamics; spike bypass and per-step state reset are available as causal controls. Neuron creation/recreation is counted as internal event work. Synthetic contract tests confirm scalar/compact equality, development no-update behavior, lifecycle rejection, and bounded spiking work.

The [synthetic episode auditor](../src/sara_engine/evaluation/cartpole_episode_audit.py) is source-pinned at SHA-256 `b33496fbef8498773695ed4df0c592e0a851a19732ff282656f6a773576826eb`. It accepts only an injected `SyntheticLifecycle-v1` environment, never constructs Gymnasium, and rejects the real `CartPole-v1` identity. It discards step rewards, gives the policy only terminal feedback, and records input events, internal work, spikes, terminal updates, deep-counted peak policy state, and process CPU for the agent path. The CPU figure excludes environment physics and reset; it includes policy reset, encoding, decisions, state measurement, and terminal update. Synthetic tests also verify that evaluation-mode feedback cannot change weights. These measurements are instrumentation checks, not benchmark results or physical energy.

The separate [development preregistration](../data/processed/benchmark_fixtures/cartpole_terminal_prereg_v1.json) is now fixed at SHA-256 `86a50d698174c220afa66bac25160caf293762fbfe7875d56a80a9efea51f392`; it pins the [real-environment runner](../src/sara_engine/evaluation/cartpole_registered_runner.py) at SHA-256 `d80aefeb7be734dde6054b5033a3eeb942bf90aca3f675afb9a051d007efa551` and all imported policy/adapter/neuron/accounting sources. It authorizes **one development run only**, not held-out evaluation. Five runs each receive exactly 128 training and 32 no-update development episodes. The six variants are A scalar, B compact, C spiking, C spike-bypass, C per-step state reset, and A no-learning. All use the same reset-seed schedule and source-pinned local rule. Exploration is re-seeded from `410000 + environment_reset_seed` at the start of every episode, so different earlier episode lengths cannot shift later arms' random streams. There is no early stopping or development tuning.

The frozen development gate requires mean C episode length ≥100; C−B ≥20 steps; C−spike-bypass ≥20; C−state-reset ≥10; C−no-learning ≥20; positive C−B in at least four of five runs; exact A/B action-and-weight parity; no development updates; and all resource limits. Peak deep-counted policy state is capped at 200,000 bytes, agent process CPU at 2 seconds per episode, and input/internal work must obey the source-pinned bounds. CPU excludes environment physics and reset but includes the state-measurement overhead; it is not physical energy. Results go only to `workspace/evaluation/cartpole_terminal_development_v1.json`. A persistent exclusive lock is reserved before scoring; even a failed execution needs review rather than an automatic retry. The result decision never itself authorizes held-out opening. A failed development gate is retained as a negative result, with no retuning or held-out access; a passed gate requires a separate reviewed held-out protocol. Different C state capacity and processing cost are measured rather than artificially equalized, so any observed advantage cannot by itself isolate spikes from extra state or compute.
